# Amobee

> Amobee was a cross-channel advertising platform (DSP, DMP, TV planning and brand
> intelligence) whose Platform API let advertisers and agencies manage advertisers,
> insertion orders, line items, packages, creatives and ads programmatically.
> Amobee was acquired by Tremor International in 2022 and the brand has since been
> absorbed into Nexxen: www.amobee.com now serves a holding page titled "Amobee is
> now Nexxen!". The platform still runs for existing customers, but the public
> developer surface has been withdrawn.

Generated by API Evangelist on 2026-08-12. Amobee publishes no llms.txt of its own
(https://www.amobee.com/llms.txt returned 404). Every statement below was probed
live on that date; nothing here is inferred.

## APIs

### Amobee Platform (Campaign) API — credential-gated, undocumented publicly
- Base URL: https://services.amobee.com/campaign/v3/api
- Auth: OAuth 2.0 client_credentials. POST https://services.amobee.com/accounts/v1/api/token
  with the client_id:client_secret pair in an HTTP Basic Authorization header; present the
  returned access_token as a Bearer token.
- Credentials are provisioned by Amobee under a signed agreement — Schedule A of the Master
  Service Terms states the API Client "will use the API through an API-only account created
  by Amobee". There is no self-service sign-up.
- Documented resources (from the terms and the retired reference): advertisers, insertion
  orders, line items, packages, creatives, ads.
- No machine-readable specification for this API is published anywhere. Do not assume
  request or response shapes.

### Amobee services gateway (public utility endpoints)
- OpenAPI 3.1.0: https://services.amobee.com/v3/api-docs (200)
- GET /files/TCFDisclosure.json — IAB TCF vendor device-storage disclosure
- GET /files/TCFDisclosure — same document
- GET /ip — echoes the resolved client IP and forwarding headers
- GET /healthcheck/status — returns "healthy"
- GET /env-vars-test — environment diagnostic
- GET /swagger-resources, GET /swagger-config — legacy springfox discovery (500 / empty)

## Conventions

- Versioning: major version in the path (/campaign/v3/api, /accounts/v1/api)
- Errors: proprietary JSON envelope {timestamp, path, status, error, requestId} — not RFC 9457
- Tracing: requestId in the body matches the x-amobee-cloud-gateway-transaction-id response header
- Rate limits: contractual, not header-signaled. No X-RateLimit-*/RateLimit-* headers observed.
  Schedule A requires API clients not to "unreasonably burden the API" and to honor Amobee
  requests to reduce volume. Social publisher inventory is additionally subject to the
  publishers' own limits (Schedule C).
- Idempotency: not documented and not observable. Do not assume retries are safe.
